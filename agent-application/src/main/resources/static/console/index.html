📖 平台架构（基于 AgentScope Java v2 Going to Production）

平台形态：Spring Boot 托管多个 HarnessAgent 单例；每次调用通过 RuntimeContext(userId, sessionId) 定位会话状态，单实例可服务并发请求，多副本共享 AgentStateStore。

存储选型：REDIS = AgentStateStore + BaseStore + 快照 + 执行锁（生产首选）；MYSQL = 状态沉淀关系库；MEMORY = 仅开发调试。

文件系统：LOCAL = 本机 shell；REMOTE = 多副本共享长期记忆（MEMORY.md/memory/skills）；DOCKER = 沙箱隔离 + 快照恢复 + 跨节点执行串行化。

关键约束：REMOTE/DOCKER 必须配分布式 store（否则构建抛 IllegalStateException，这是设计如此）；生产禁止用 MEMORY store + 多副本。

租户隔离：userId 拼租户前缀（如 tenantA:alice），agentId 拼进 sessionId；生产每次调用必须显式传 RuntimeContext，防止 defaultSessionId 串台。

可观测：平台自研 Middleware 采集调用/延迟/错误指标；可选 OpenTelemetry tracing（设置 observability.otelTracing=true + OTLP endpoint）。

Skill 治理：开启 skillRepository.enabled=true + writeable=false，agent 端只读分发，改 skill 走管理台。
