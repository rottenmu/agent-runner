# 智能体管理完善方案

## 目标

围绕 `ai-agent-spring-boot-starter` 与前端 `frontend/modules/ai`，把智能体管理从页面配置能力完善为可持久化、可绑定、可运行的闭环能力。最终效果是：用户可以在智能体管理中创建智能体、创建技能、维护 CoSTAR 提示词模板，并让飞书渠道中的项目管理智能体按绑定配置真实生效。

## 当前现状

- 前端已有智能体管理入口，页面文件为 `frontend/modules/ai/src/views/AiAgentManage.vue`。
- 前端已有智能体、技能、提示词模板 API 封装，文件为 `frontend/modules/ai/src/api/agent.js`。
- 后端已有统一管理接口，控制器为 `AiAgentManagementController`，路径前缀为 `/api/ai`。
- 后端已有技能配置持久化能力，主要面向 `ai_agent_skill_config`。
- 提示词模板已有生命周期管理能力，表为 `ai_prompt_template`。
- 智能体配置当前主要保存在内存 `Map` 中，重启后会丢失。
- 飞书渠道运行时会根据渠道查找默认智能体，但提示词模板和技能绑定尚未完整参与运行时装配。

## 完善范围

### 一、智能体持久化

新增智能体配置表 `ai_managed_agent`，用于保存管理端创建和编辑的智能体。数据表要求：

- 使用 MySQL。
- 表注释、字段注释全部使用中文。
- 只保留主键索引，不创建额外普通索引。
- 使用逻辑删除，不进行物理删除。
- starter 不新增 MySQL 表初始化器，不在启动时自动创建该表；表结构由平台输出 SQL 草案，经确认后通过外部数据库变更流程执行。
- 保存智能体基础信息、模型、persona、提示词模板、绑定技能、默认渠道、启用状态和创建人信息。

### 二、默认项目管理智能体

系统初始化一个独立的默认项目管理智能体，而不是把所有默认角色改成项目管理智能体。该智能体默认面向飞书渠道，绑定项目管理相关技能：

- 解析 Excel 类型文件用于生成项目。
- 生成项目编码。
- 查看项目编码。
- 查看所有项目视图。

该智能体提示词要求输出标准化结构化 JSON，供后端组装飞书 interactive CardKit 卡片。

### 三、技能管理闭环

技能管理继续复用现有技能注册和 API 技能配置能力，并补齐以下运行规则：

- 技能新增、编辑、删除均可从智能体管理页面完成。
- 技能可以绑定技能提示词模板。
- 删除技能时，同步从已绑定智能体中移除。
- API 技能的启用状态参与运行时判断。
- API 技能的超时时间真实作用到请求调用。

### 四、提示词模板分型

提示词模板分为两类：

- 智能体提示词模板。
- 技能提示词模板。

创建智能体时只能引用智能体提示词模板；创建技能时只能引用技能提示词模板。所有模板继续遵循 CoSTAR 规范，支持手动创建和按业务描述自动生成。

### 五、飞书 CardKit 返回链路

项目管理智能体返回数据时，不再操作飞书多维表格，也不再创建飞书表格。新的返回链路为：

1. 智能体输出标准化结构化 JSON。
2. 后端解析 JSON。
3. 后端组装飞书 interactive CardKit 卡片。
4. 通过飞书机器人发送到群聊或单聊。

JSON 必须包含三类核心数据：

- `headers`：表头配置。
- `rows`：表格数据。
- `actions`：按钮配置。

可选扩展数据：

- `layout`：多栏布局和全屏宽度配置。
- `statusBlocks`：状态色块。
- `streamSections`：流式分段渲染数据。

智能体禁止输出长文本、Markdown 和多余注释。

### 六、前端菜单与页面优化

智能体管理菜单下维护二级菜单：

- 智能体列表。
- 技能管理。
- 提示词管理。

前端页面后续拆分为更小组件，避免 `AiAgentManage.vue` 继续膨胀：

- `AgentListPanel.vue`
- `AgentFormDialog.vue`
- `SkillListPanel.vue`
- `SkillFormDialog.vue`
- `AiPromptTemplateManage.vue`

同时去掉当前硬编码用户，改为从登录用户上下文获取。

## 推荐执行顺序

### 任务一：智能体持久化

- 新增 `AiManagedAgentConfig` 数据对象。
- 新增 `AiManagedAgentRepository` 仓储接口。
- 新增 JDBC 实现。
- 输出 MySQL 表结构 SQL 草案，待确认后由外部数据库变更流程执行。
- 改造 `AiAgentManagementService`，让智能体 CRUD 读写 MySQL。
- 保留 contributor 和默认种子智能体初始化逻辑。

### 任务二：默认项目管理智能体

- 新增默认项目管理智能体 contributor 或种子初始化逻辑。
- 绑定飞书默认渠道。
- 绑定项目管理技能名称。
- 内置项目管理智能体提示词约束：返回 CardKit JSON。

### 任务三：运行时装配

- 飞书渠道选择默认智能体后，加载智能体提示词模板。
- 根据智能体绑定技能限制可调用技能范围。
- 技能提示词模板作为技能调用说明参与上下文。
- API 技能启停和超时配置在运行时生效。

### 任务四：CardKit 渲染

- 新增结构化 JSON 模型。
- 新增 CardKit 卡片构建服务。
- 飞书消息发送前识别结构化数据并发送 interactive 卡片。
- 保留普通文本兜底。

### 任务五：前端优化

- 调整智能体管理菜单为二级菜单。
- 创建智能体时过滤智能体提示词模板。
- 创建技能时过滤技能提示词模板。
- 拆分页面组件。
- 去掉硬编码用户。

## 验证策略

- 后端新增仓储和 schema initializer 单元测试。
- 管理服务新增智能体 CRUD 持久化测试。
- 技能删除联动智能体绑定测试。
- 飞书 CardKit JSON 渲染单元测试。
- 前端执行最窄范围构建验证。

## 第一阶段交付

第一阶段优先完成智能体持久化和默认项目管理智能体初始化，确保管理端创建的智能体不会因为服务重启丢失，并为飞书渠道后续运行时装配打基础。
