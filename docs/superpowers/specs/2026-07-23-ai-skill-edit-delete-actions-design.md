# 智能体管理技能编辑删除设计

## 背景

智能体管理的技能页面已经支持创建 API 技能，并且后端已经具备更新、删除 API 技能的接口能力。当前页面需要把编辑、删除能力补齐为用户可见、可验证、体验一致的完整功能，同时保持内置 Bean 技能的只读边界。

## 目标

1. 技能页面中的自定义 API 技能支持编辑。
2. 技能页面中的自定义 API 技能支持删除。
3. 创建技能时选择的 API 注册表信息可以在编辑时回显，并在保存后继续持久化。
4. 内置技能只读展示，不允许编辑和删除。
5. 修复技能页面相关中文文案乱码，保证页面可读。
6. 补充前端验证，避免后续重构破坏技能操作入口。

## 非目标

1. 不允许编辑或删除后端 Bean 注册的内置技能。
2. 不调整智能体运行时调用协议。
3. 不新增新的技能数据表结构，沿用当前已支持的 API 技能配置持久化字段。
4. 不改变前端主壳端口配置。

## 前端交互设计

### 技能列表

- 自定义 API 技能卡片显示「编辑」「删除」按钮。
- 内置技能显示「内置技能」标识，不显示危险操作按钮。
- API 技能卡片保留提示词模板绑定能力。
- 技能被智能体引用时，删除确认文案明确提示会同步移除绑定关系。

### 创建技能

- 创建技能仍通过现有技能抽屉完成。
- 用户从已注册接口中搜索选择接口后，自动填充 `path`、`method`、`summary` 等 API 配置信息。
- 保存时提交 `apiRegistryId`，用于后续编辑回显和数据库持久化。

### 编辑技能

- 点击「编辑」后打开同一个技能抽屉。
- 技能名称保持不可修改，避免破坏技能标识和智能体绑定关系。
- 可编辑字段包括：描述、启用状态、API 注册表选择、请求路径、请求方法、参数映射、提示词模板等现有配置项。
- 保存时调用后端更新接口，成功后刷新技能列表或更新当前卡片状态。

### 删除技能

- 点击「删除」后弹出确认框。
- 确认后调用删除接口。
- 删除成功后从技能列表移除，并从已加载智能体的 `skillIds` 中同步移除该技能。
- 删除失败时保留原列表状态，并展示后端错误信息。

## 后端接口沿用

当前后端接口已满足方案 A，不新增接口：

- `POST /api/ai/skills`：创建 API 技能。
- `PUT /api/ai/skills/{name}`：编辑 API 技能。
- `DELETE /api/ai/skills/{name}`：删除 API 技能。
- `GET /api/biz/sys/api-registry`：搜索选择已注册接口。

后端继续保持保护规则：

- 仅允许操作 `source = api` 的自定义技能。
- 内置 Bean 技能编辑或删除时返回业务错误。
- 删除 API 技能时同步解除智能体绑定关系。

## 数据保存规则

- 技能 API 配置继续保存到当前技能配置持久化结构。
- `apiRegistryId` 表示当前技能关联的 API 注册表记录。
- 用户手动修改 path/method 后，仍保留已选择的 `apiRegistryId`，除非用户主动清空已选接口。
- API 注册表记录不存在或不可访问时，编辑表单仍展示已保存的 path/method，避免历史配置丢失。

## 验收标准

1. 技能页进入「技能」Tab 后，自定义 API 技能卡片能看到「编辑」「删除」。
2. 点击编辑后可以正确回显创建时保存的 API 注册表、path、method 和参数配置。
3. 编辑保存后刷新页面，修改内容仍存在。
4. 删除自定义 API 技能后，技能列表不再展示该技能。
5. 被智能体引用的 API 技能删除后，相关智能体绑定列表中不再包含该技能。
6. 内置技能不会展示删除入口，且后端仍禁止删除。
7. 技能页面中文文案显示正常，没有乱码。
8. 前端测试和构建通过。

## 验证计划

1. 增加或扩展 `frontend/modules/ai/tests` 下的静态测试，覆盖技能编辑、删除操作入口和 API 调用封装。
2. 执行 AI 模块前端相关 Node 测试。
3. 执行 `frontend/web-shell` 构建验证。
4. 如后端代码未变更，则复用已有后端 CRUD 测试结果；若调整后端保护逻辑，再执行 AI starter 相关 Maven 测试。

## 风险与处理

- 风险：已有页面文件存在中文乱码，直接小范围补按钮可能继续影响页面可读性。
  - 处理：本次一并修复技能页相关中文文案。
- 风险：删除被引用技能后前端本地智能体数据未同步。
  - 处理：删除成功后同步清理本地 `agents.skillIds`，必要时重新拉取技能和智能体列表。
- 风险：内置技能误操作。
  - 处理：前端不暴露入口，后端继续基于 `source` 做强校验。
