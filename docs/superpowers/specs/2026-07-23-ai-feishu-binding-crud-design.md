# 飞书渠道绑定 CRUD 设计

## 1. 背景

当前“飞书渠道绑定”页面以飞书配置为主列表，在每行中直接选择智能体，并通过“解除绑定”按钮清空 `ps_feishu_config.agent_id`。

该页面已经具备保存和解除绑定的底层能力，但没有形成清晰的绑定关系管理流程：

- 主列表同时展示已绑定和未绑定飞书配置；
- 没有独立的“新增绑定”入口；
- 编辑操作与表格下拉选择耦合；
- 用户难以把“飞书配置”和“飞书—智能体绑定关系”区分开。

本次将页面调整为只管理绑定关系，并提供明确的新增、编辑和删除操作。

## 2. 目标

- 主列表只展示已经绑定智能体的飞书配置。
- 增加独立的“新增绑定”功能。
- 增加独立的“编辑绑定”功能。
- 增加“删除绑定”功能，删除仅表示解除绑定。
- 新增时只能选择尚未绑定的飞书配置。
- 编辑时不允许切换飞书配置，只允许更换智能体。
- 新增和编辑时只能选择已启用的智能体。
- 保留失效绑定的展示、编辑和删除能力。
- 不增加数据库表或字段，不修改运行时消息路由。
- 复用现有绑定保存接口，避免重复后端逻辑。

## 3. 方案选择

### 3.1 采用方案

复用现有接口：

```text
PUT /api/biz/feishu/config/{id}/agent-binding
```

请求体：

```json
{
  "agentId": "a123"
}
```

操作语义：

- 新增：未绑定飞书配置写入非空 `agentId`；
- 编辑：已绑定飞书配置替换为新的非空 `agentId`；
- 删除：已绑定飞书配置写入 `agentId=null`。

飞书配置分页接口增加可选参数 `bound`，用于区分已绑定和未绑定配置。

该方案不引入新的关联实体，保持 `ps_feishu_config.agent_id` 为绑定关系的唯一数据源。

### 3.2 未采用方案

#### 新增 POST、PUT、DELETE 三套绑定接口

三套接口最终执行相同的单字段更新，会产生重复的 Controller、Service 和测试代码。当前绑定没有独立主键，复用现有幂等更新接口更直接。

#### 新建飞书—智能体关联表

关联表适合一条飞书配置绑定多个智能体、按规则路由等复杂场景。当前是一对一绑定，新表会增加同步、唯一约束和迁移成本。

## 4. 后端设计

### 4.1 分页筛选参数

扩展接口：

```text
GET /api/biz/feishu/config/page
```

新增可选查询参数：

```text
bound: Boolean
```

查询规则：

- `bound=true`：仅查询 `agent_id IS NOT NULL` 的配置；
- `bound=false`：仅查询 `agent_id IS NULL` 的配置；
- 未传 `bound`：不按绑定状态筛选，保持原接口兼容；
- 空字符串已由绑定 Service 规范化为 `null`，数据库中不使用空字符串表示未绑定。

`FeishuConfigController.page` 和 `FeishuConfigService.page` 增加 `Boolean bound` 参数，`FeishuConfigServiceImpl` 使用 MyBatis-Plus 查询条件：

```java
if (Boolean.TRUE.equals(bound)) {
    wrapper.isNotNull(FeishuConfigEntity::getAgentId);
} else if (Boolean.FALSE.equals(bound)) {
    wrapper.isNull(FeishuConfigEntity::getAgentId);
}
```

### 4.2 绑定写入接口

新增、编辑和删除继续调用现有绑定接口，不增加新的写接口。

后端继续执行以下约束：

- `agentId` 去除首尾空格；
- 空值或空白值转换为 `null`；
- 非空 `agentId` 最大长度为 64；
- Mapper 只更新 `agent_id`，不覆盖飞书配置其他字段；
- 更新不到唯一配置时返回业务错误。

`module-feishu` 不直接校验智能体是否存在或启用，以保持其与 `module-ai` 的依赖边界。前端限制可选值，AI 运行时继续做最终有效性校验和降级。

## 5. 前端设计

### 5.1 页面主列表

页面加载时请求：

```text
GET /biz/feishu/config/page?bound=true
GET /biz/ai/agents
```

主列表只展示已绑定关系，保留以下字段：

- 配置名称；
- App ID；
- 租户；
- 飞书配置启用状态；
- 凭据状态；
- 当前智能体；
- 绑定状态；
- 操作。

操作列只提供：

- 编辑；
- 删除。

移除表格内直接选择智能体的下拉框，避免修改操作与列表浏览混在一起。

### 5.2 新增绑定

页面顶部增加“新增绑定”按钮，打开独立弹窗。

弹窗字段：

- 飞书配置：必选、可搜索；
- 智能体：必选、可搜索。

飞书配置候选通过以下请求加载：

```text
GET /biz/feishu/config/page?bound=false
```

候选项展示配置名称和 App ID。只允许选择未绑定配置，避免覆盖已有关系。

智能体候选项仅包含 `enabled=true` 的智能体。

提交前端校验：

- 未选择飞书配置时提示“请选择飞书配置”；
- 未选择智能体时提示“请选择智能体”；
- 保存期间禁用重复提交。

提交成功后：

- 关闭弹窗；
- 刷新已绑定主列表；
- 刷新未绑定配置候选；
- 显示“绑定新增成功”。

### 5.3 编辑绑定

点击“编辑”打开同一弹窗的编辑模式。

编辑规则：

- 飞书配置只读，展示配置名称和 App ID；
- 智能体必选；
- 当前绑定智能体仍启用时默认选中；
- 当前绑定已失效时，下拉框不伪造失效选项，要求重新选择启用智能体；
- 新智能体与原智能体相同时允许关闭弹窗，不重复调用保存接口。

保存成功后关闭弹窗、刷新主列表并提示“绑定修改成功”。

### 5.4 删除绑定

点击“删除”显示二次确认：

```text
确认删除飞书配置“{配置名称}”与智能体“{智能体名称}”的绑定关系？
```

确认后调用现有绑定接口并传入：

```json
{
  "agentId": null
}
```

删除只解除关系，不删除：

- 飞书配置；
- 智能体；
- 飞书历史消息或日志。

删除成功后：

- 从已绑定列表移除该行；
- 该飞书配置重新进入未绑定候选；
- 显示“绑定删除成功”。

取消确认时不发起请求。

### 5.5 弹窗状态

弹窗使用独立表单状态：

```text
mode: create | edit
configId
agentId
originalAgentId
```

关闭弹窗时清空表单和校验状态，避免新增与编辑之间残留数据。

页面继续按飞书配置 ID 维护保存中状态，防止并发操作相互提前解锁。

## 6. 数据流

### 6.1 新增

```text
打开新增弹窗
  → 加载 bound=false 飞书配置
  → 选择飞书配置和启用智能体
  → PUT agent-binding
  → 刷新 bound=true 主列表
```

### 6.2 编辑

```text
点击已绑定关系
  → 锁定飞书配置
  → 选择新的启用智能体
  → PUT agent-binding
  → 刷新当前列表
```

### 6.3 删除

```text
点击删除
  → 二次确认
  → PUT agent-binding，agentId=null
  → 刷新已绑定列表和未绑定候选
```

## 7. 异常处理

- 主列表加载失败：保留当前列表数据并显示错误信息。
- 未绑定候选加载失败：弹窗保持打开，禁用提交并提示重新加载。
- 智能体列表加载失败：保留当前列表数据，新增和编辑不可提交。
- 新增保存失败：弹窗保持打开，保留用户选择。
- 编辑保存失败：弹窗保持打开，主列表不提前修改。
- 删除失败：保留当前行和绑定状态。
- 绑定在操作期间被其他用户修改：以后端最后成功写入为准，成功后重新加载列表。
- 飞书配置已删除或更新影响行数不是 1：显示后端业务错误并刷新列表。

## 8. 兼容性与安全

- `bound` 为新增可选参数，原调用方不传时行为不变。
- 数据库结构和手工执行 SQL 不变。
- AI 运行时路由和飞书消息处理不变。
- 页面不展示 `appSecret`、`verificationToken` 或 `encryptKey`。
- 删除绑定不触发任何物理删除。
- `module-feishu` 与 `module-ai` 不增加 Maven 依赖。

## 9. 测试范围

### 9.1 后端测试

- `bound=true` 生成 `agent_id IS NOT NULL` 查询条件；
- `bound=false` 生成 `agent_id IS NULL` 查询条件；
- 未传 `bound` 时不增加绑定条件；
- Controller 正确透传 `bound`；
- 原分页参数和调用方式保持兼容；
- 绑定保存、解除和只更新 `agent_id` 的测试继续通过。

### 9.2 前端测试

- 主列表请求包含 `bound=true`；
- 未绑定候选请求包含 `bound=false`；
- 页面包含“新增绑定”“编辑”“删除”入口；
- 主表不再包含行内绑定下拉；
- 新增时飞书配置和智能体必选；
- 编辑时飞书配置不可修改；
- 失效绑定编辑时必须重新选择智能体；
- 相同智能体不重复提交；
- 删除前显示二次确认；
- 取消删除不调用接口；
- 请求失败时不提前修改列表；
- 页面不包含飞书敏感字段。
