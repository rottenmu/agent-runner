# 飞书渠道绑定导航与解绑能力设计

## 目标

完善飞书渠道绑定页面的导航和操作入口：顶部提供返回智能体管理与新增绑定飞书按钮；已绑定记录提供明确的解绑操作，并保留编辑、删除能力。

## 页面交互

### 顶部操作区

顶部按钮从左到右为：

1. 返回智能体管理；
2. 刷新；
3. 新增绑定飞书。

“返回智能体管理”跳转到 `/ai/agents`。“新增绑定飞书”复用现有新增绑定弹窗和候选加载逻辑；现有“新增绑定”按钮改名，不保留重复入口。

### 表格行操作

已绑定飞书配置的行操作顺序为：

1. 解绑；
2. 编辑；
3. 删除。

解绑前显示确认提示，说明只解除飞书配置与智能体的关系。解绑成功后刷新已绑定列表和未绑定候选列表；飞书配置与智能体数据均不删除。

编辑继续用于更换绑定的智能体。删除保留现有语义与行为，不因本次调整变更。

## 接口设计

保留已有绑定接口：

```text
PUT /api/biz/feishu/config/{id}/agent-binding
{
  "agentId": "智能体ID 或 null"
}
```

增加语义明确的解绑接口：

```text
PUT /api/biz/feishu/config/{id}/agent-unbinding
```

Controller 调用已有 `FeishuConfigService.bindAgent(id, null)`。不新增表、字段、SQL、初始化器或 Service 方法；数据层继续只更新 `ps_feishu_config.agent_id`。

前端新增 `unbindFeishuAgent(configId)` API 封装，调用 `agent-unbinding` 接口。行内“解绑”只调用此方法，不复用删除飞书配置接口。

## 错误处理

- 用户取消解绑确认时不发请求、不修改列表。
- 解绑接口失败时保留当前列表，显示后端错误信息。
- 解绑成功但刷新失败时，沿用页面现有 `Promise.allSettled` 刷新策略，仅显示刷新警告，不误报解绑失败。

## 测试

后端测试覆盖：

- `PUT /{id}/agent-unbinding` 调用 Service 且参数为 `null`；
- 返回脱敏的飞书配置响应。

前端静态契约覆盖：

- 返回按钮跳转 `/ai/agents`；
- 顶部使用“新增绑定飞书”且不保留“新增绑定”文案；
- 行操作的文本顺序为解绑、编辑、删除；
- `unbindFeishuAgent` 请求 `agent-unbinding`；
- 解绑流程包含确认、错误提示和刷新。

完成后运行飞书后端相关测试、AI 模块 Node 测试和 `frontend/web-shell` 生产构建。

## 非目标

- 不改变智能体管理页入口或飞书绑定页面路由。
- 不修改绑定、编辑、删除的既有业务规则。
- 不增加数据库迁移或运行时消息路由变更。
