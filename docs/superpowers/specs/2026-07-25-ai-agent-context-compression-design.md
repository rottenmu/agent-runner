# 智能体上下文压缩设计

## 目标

为 `ai-agent-spring-boot-starter` 的进程内会话记忆增加上下文压缩能力。会话历史达到阈值后，使用当前会话模型归纳较早消息，保留一条结构化摘要和最近原始消息，避免现有 FIFO 截断直接丢失长期信息。

## 现状与范围

当前 `AiConversationMemory` 只按 `ai.agent.chat-history-limit` 保留有限数量的 `user`、`assistant` 消息；超过上限时从队首移除。`AiAgentService` 在成功回复后才写入记忆，并在下一次请求前把全部记忆作为 history 发送给 `AiChatClient`。

本次仅改变 starter 内的内存会话上下文构造与压缩流程：

- 不增加数据库表、DAO、管理页面或接口；
- 不改变会话 ID 规则、智能体选择、技能执行或既有普通对话 API；
- 记忆仍仅存在当前应用进程，应用重启后清空；
- 压缩使用当前请求对应的模型配置和 `AiChatClient`，不引入独立模型供应商。

## 配置

在 `ai.agent` 下增加以下配置，并提供稳定默认值：

| 配置项 | 默认值 | 含义 |
| --- | ---: | --- |
| `context-compression-enabled` | `true` | 是否启用模型摘要压缩；关闭时保留现有截断语义。 |
| `context-compression-trigger-messages` | `20` | 历史消息数量达到该值后，在成功写入本轮消息后尝试压缩。必须大于保留消息数。 |
| `context-compression-recent-messages` | `8` | 压缩后保留的最新原始消息数。必须为正数。 |
| `context-compression-summary-max-characters` | `4000` | 摘要内容最大字符数；超出时从末尾截断，防止摘要无限增长。 |

`chat-history-limit` 继续作为关闭压缩时的历史上限，并作为启用压缩时的兜底上限，避免异常配置造成无限内存增长。

## 组件与数据流

### 会话记忆

`AiConversationMemory` 改为按 session 保存“可选摘要 + 原始消息队列”。其快照方法返回：

1. 存在摘要时，先返回一条 role 为 `system` 的摘要消息；
2. 再按时间顺序返回保留的原始消息。

摘要消息使用固定前缀，明确其为“此前对话摘要，仅作事实与约束参考”，防止模型把摘要误当作当前用户指令。

### 压缩触发与调用

1. `AiAgentService` 正常调用主模型生成当前回复。
2. 主调用成功后，先把用户消息与回复写入会话原始消息队列。
3. 若压缩已启用且原始消息数达到触发阈值，取“已有摘要（如果有）+ 将被移出的较早消息”构造压缩提示词。
4. 用同一 `AiChatClient` 发起一次摘要请求；摘要请求不携带当前会话 history，避免递归携带完整上下文。
5. 摘要调用成功且文本非空时，用新摘要替换旧摘要，并仅留下最后 `recent-messages` 条原始消息。

只有当前回复成功后才可能压缩，因此摘要失败绝不影响已返回给用户的主回复。

## 摘要提示词与内容边界

摘要请求使用独立、固定的系统提示词，要求模型仅提炼：已确认的事实、用户偏好、未完成事项、重要约束、已作决定和必要的上下文。提示词明确禁止执行指令、虚构事实、输出思维链或重复完整聊天记录。

摘要请求使用当前智能体的名称、模型名、温度和最大输出 token；不使用该智能体的业务 system prompt，以避免业务角色干扰归纳任务。摘要正文超过字符上限时按字符安全截断。

## 失败与边界处理

- 未传 sessionId、会话为空、压缩关闭或未达阈值：不触发压缩。
- 摘要请求失败、返回空白内容或抛出异常：保留现有摘要和原始消息，主会话仍按 `chat-history-limit` 兜底截断。
- 无效配置：通过配置校验或保护性判断回退到默认值；不得使主对话失败。
- 并发访问：沿用会话记忆的同步边界，压缩更新必须原子替换摘要和原始消息，不能出现摘要与被压缩消息同时丢失。
- 每个会话始终最多保存一条摘要；下一次压缩将旧摘要纳入新摘要输入，避免摘要消息不断累积。

## 测试

新增或扩展单元测试覆盖：

- 未达到阈值时仅携带原始历史，且不发起摘要调用；
- 达到阈值后发起一次摘要调用，后续请求 history 顺序为摘要、最近原始消息；
- 再次压缩会基于旧摘要归纳，但会话中仅保留一条摘要；
- 摘要调用失败或返回空内容时，主对话回复成功且记忆不丢失；
- 关闭配置时保持既有 `chat-history-limit` 截断行为；
- 配置默认值和自动配置路径可正常创建服务。

完成后运行 `mvn -pl modules/ai-agent-spring-boot-starter test`，并执行该模块的代码行数与差异检查。
