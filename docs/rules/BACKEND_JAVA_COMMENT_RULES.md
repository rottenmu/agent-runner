# 后端 Java 代码注释规则

本文定义本仓库后端 Java 代码生成、修改和评审时必须遵守的注释规则。适用范围包括 `framework/`、`modules/`、`admin-shell/` 下的 Java 后端代码，以及后续新增的 Spring Boot 插件模块。

## 全局强制规则

- 所有后端 Java 公共类、公共方法、实体字段必须使用中文 JavaDoc 注释。
- 注释使用中文描述业务含义，类名、变量名、接口路径、数据库表名、枚举编码等保持英文原样。
- 注释必须说明业务用途、参数约束、返回值含义、异常场景和特殊规则。
- 禁止只复述代码语法的冗余注释，例如“设置属性”“返回结果”“调用方法”。
- 注释应兼容 IDEA、JavaDoc、Swagger/OpenAPI、Lombok 和飞书文档解析。
- 涉及租户字段、软删除字段、金额字段、时间字段、分页参数时，必须标明特殊业务规则。
- 日期统一使用 `yyyy-MM-dd` 格式。
- 生成或修改 Java 后端代码时，如果缺少本规则要求的必填注释，应先补齐注释后再交付。

## 实体类、DO、VO、DTO

### 类注释

实体类、DO、VO、DTO 的类头 JavaDoc 必须包含：

- 所属业务模块。
- 类型用途，例如数据库实体、接口入参、接口出参、页面展示对象。
- 对应数据库表名。DO、Entity 必须标注表名；VO、DTO 无需标注表名。
- 特殊业务说明，例如租户隔离、软删除、金额单位、时间自动填充。
- 作者。
- 创建日期，格式为 `yyyy-MM-dd`。

### 字段注释

- 所有字段必须逐条添加 JavaDoc 注释。
- 主键字段必须说明主键来源和业务唯一性边界。
- 租户 ID 必须说明它是数据隔离维度。
- 软删除字段必须说明 `0` 表示正常、`1` 表示已删除，并注明禁止物理删除。
- 金额字段必须说明单位为分，前端展示时需要换算。
- 自动填充时间字段必须说明由系统维护，无需手动赋值。
- 分页字段必须说明默认值、最大值和越界处理规则。

## Mapper 层

### 接口注释

Mapper 接口类头 JavaDoc 必须包含：

- 所属业务模块。
- 对应数据库表名。
- 核心数据访问能力。
- 编码约束：Mapper 只负责单表或清晰边界的数据操作，复杂业务逻辑应下沉到 Service 层。

### 方法注释

所有 Mapper 公共方法必须说明：

- 入参含义。
- 入参是否允许为空。
- 返回值含义。
- 空数据返回规则，例如返回空列表、`null` 或 `Optional.empty()`。
- 数据查询或写入范围。

Mapper 注释只说明数据操作范围和参数约束，不描述复杂业务流程。

## Service 层

### Service 接口注释

Service 接口类头 JavaDoc 必须包含：

- 所属业务模块。
- 整体业务能力。
- 事务边界和事务规则。

### ServiceImpl 实现类注释

ServiceImpl 类头 JavaDoc 必须包含：

- 实现的业务能力。
- 依赖的核心服务或外部组件。
- 事务传播规则。
- 统一异常抛出规范。

### 业务方法注释

所有业务方法必须完整说明：

- 业务执行流程。
- 入参对象的必填字段。
- 参数合法性约束。
- 返回值含义。
- 可能抛出的业务异常场景和原因。
- 涉及权限、租户、数据范围、状态流转时的特殊规则。

私有复杂方法不强制 JavaDoc，但方法体前应添加简洁的单行中文业务说明。

## Controller 层

### 控制器注释

Controller 类头 JavaDoc 必须包含：

- 所属业务模块。
- 接口统一前缀。
- 接口权限规则。
- 返回体规范。

### 接口方法注释

所有接口方法注释必须兼容 Swagger/OpenAPI 可读性，并说明：

- 请求路径和接口用途。
- 请求参数含义。
- 参数默认值。
- 参数限制，例如最大条数、必填或选填、枚举取值范围。
- 返回数据结构说明。
- 鉴权、白名单、数据权限等特殊规则。

## 常量类和枚举类

### 常量类

- 类头注释说明整体用途和适用业务场景。
- 每个常量必须单独注释业务含义。
- 配置键、权限标识、缓存键、消息主题等常量必须说明命名规则和使用范围。

### 枚举类

- 类头注释说明所属业务场景。
- 每个枚举项必须注释对应业务状态。
- 枚举编码、描述字段必须逐条注释。
- 如果枚举编码会入库或对接前端，必须说明兼容性要求，禁止随意修改。

## 工具类和异常类

### 工具类

工具类类头 JavaDoc 必须说明：

- 整体功能。
- 使用方式，例如仅提供静态方法、禁止实例化。
- 适用边界。

公共工具方法必须说明：

- 参数校验规则。
- 返回值含义。
- 特殊处理逻辑，例如精度换算、格式化、空值处理。

### 异常类

自定义异常类必须说明：

- 异常适用场景。
- 推荐抛出位置。
- 全局异常处理逻辑。
- 返回给前端的错误语义。

## 单行注释、TODO 和 FIX

- 复杂业务逻辑代码块头部必须添加单行中文业务说明。
- 临时调试代码必须添加 `TODO` 标记和待处理说明，并在交付前尽量移除。
- Bug 修复相关代码如需保留说明，使用 `FIX yyyy-MM-dd` 标记并写清修复内容。
- 禁止无意义注释，禁止用注释重复解释基础语法。

## 交付检查清单

交付后端 Java 代码前，必须确认：

- 公共类已补齐中文 JavaDoc。
- 公共方法已说明业务用途、入参、返回值和异常场景。
- 实体字段已逐条注释。
- DO、Entity 已标注数据库表名。
- DTO、VO 未强行标注数据库表名。
- 金额、租户、软删除、时间、分页字段已标注特殊规则。
- Controller 注释对前端和 Swagger/OpenAPI 可读。
- Service 注释能看出完整业务流程和事务边界。
- 注释没有复述代码语法，没有空泛描述。

## 极简提示词

生成或修改 Java 后端代码时，严格执行中文注释规范：实体类标注业务模块、用途、表名、租户隔离、软删除规则、金额单位；Mapper 标注表名、数据操作范围、参数非空约束；Service 方法详细说明业务流程、入参必填项、异常场景和返回值含义；Controller 注释兼容 Swagger/OpenAPI，标注参数默认值与限制；常量和枚举逐条释义；所有公共类、公共方法、实体字段必须带标准 JavaDoc 中文注释；临时代码加 TODO，修复说明加 FIX 日期；禁止冗余复述代码，保持格式统一。
