# 工作流设计器现状 × Dify 风格需求 对比

> 日期：2026-08-22 ｜ 现状代码：`frontend/modules/workflow/src/views/WorkflowDesigner.vue`（1027 行）+ `WorkflowManage.vue`（550 行）
> 需求：Dify 风格可视化工作流编排编辑器（拖拽节点/连线/配置面板/运行模拟）

## 一、现状能力（已阅读核实的代码事实）

| 区域 | 现状实现 |
|---|---|
| 图库 | **Vue Flow**（`@vue-flow/core` + Background + Controls），与需求指定的 @xyflow 系一致 |
| 顶部工具栏 | 返回 / 状态标签 / **断点调试开关** / **AI 生成工作流** / 保存 / 发布 / 运行 / 单步 / 恢复 / 批准 / 驳回 / 停止 / 失败重试配置 / 运行状态条 |
| 左侧节点库 | 8 类：`start`开始 / `end`结束 / `task`任务 / `condition`条件 / `loop`循环 / `async_task`异步 / `manual`人工 / `fallback`兜底（拖拽到画布） |
| 画布 | nodes/edges 双向绑定、smoothstep 连线带箭头（animated）、拖放创建、Canvas hint、AI 生成应用到画布 |
| 右侧配置面板 | 按类型条件渲染：节点名称；task 的**任务类型（LLM/API/技能/回显）**+ 指令模板语法（input.xxx）+ 失败重试/间隔；condition 的 **SpEL 表达式**；loop 循环体；manual 人工说明；fallback 降级 |
| 运行控制 | run / pause / step / approve / stop + 状态标签（运行中/断点暂停/等待人工/成功/失败/已停止）+ 运行参数（失败重试次数） |

## 三、结论与改造建议

### 已具备且超配（无需重做）
可视化画布（Vue Flow）、拖拽/连线/缩放、按类型配置面板框架、条件 SpEL 分支、运行控制（run/pause/step/approve/stop）、AI 生成工作流。

### 核心差距（按需求补齐）
1. **节点细分**：新增 `llm` / `http` / `code` / `template` 4 类专属节点（保留 task 兼容），每类专属配置表单：
   - LLM：模型选择 + 系统提示词 + 输入变量映射
   - HTTP：method / url / headers / body
   - Code：JS 代码编辑区 + 输入输出变量
   - Template：模板文本 + 变量引用（`{{ input.xxx }}`）
2. **运行模拟可视化**：node.data.status 驱动节点边框/脉冲状态色（等待灰/运行中蓝/成功绿/失败红）+ 执行路径连线高亮流动 + 每节点输出变量预览
3. **预置示例**：一键加载"开始→LLM→条件→(是)HTTP/(否)模板→结束"
4. **导出 JSON** 按钮（workflow JSON 下载）
5. 开启画布**框选**（selectionMode）

### 交付形式确认（重要）
- **方案 A（项目内改造）**：在现有 WorkflowDesigner.vue 上增量实现上述差距——复用 Vue Flow/配置面板/运行链路，成本低、与平台一致
- **方案 B（独立单页交付）**：按需求"单文件 HTML + CDN + 深色 Dify 风格"新建独立 demo 页（现有代码可作参考实现）——独立可分享，但与项目架构分离
