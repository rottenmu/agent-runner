# 记忆总览页聚合五类记忆数据 — 方案

## 背景与目标

当前「记忆管理」页（`frontend/modules/agentmemory/src/views/MemoryManageTabs.vue`）用 6 个 Tab 平铺：

记忆总览 / 用户记忆 / 会话记忆 / 全局记忆 / 溯源分析 / 记忆策略

其中「记忆总览」（`MemoryDashboard.vue`）目前**只展示 OLAP 分析数据**（会话 KPI、行为时序、L0 事件构成、会话排行、画像配置管理），
**看不到** 用户记忆、会话记忆、全局记忆、溯源分析、记忆策略的实质数据——这些分散在其余 5 个 Tab，需逐个切换才能查看。

**目标**：在「记忆总览」Tab 内新增「记忆数据速览」区块，一屏同时呈现五类数据概况，并支持一键跳转对应 Tab 查看明细。

## 布局设计（总览 Tab 结构）

```
┌─────────────────────────────────────────────────────────────┐
│ 记忆总览（页头 + 刷新按钮）                                    │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │
│ │ 用户记忆 │ │ 会话记忆 │ │ 全局记忆 │ │ 溯源分析 │ │ 记忆策略 │ │  ← 5 张指标头卡
│ │ N 条    │ │ N 条    │ │ N 条    │ │ N trace │ │ 开关态  │ │     (24 栅格 / 每卡 4.8)
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────────── 五类数据速览（上：最近记录） ───────────────┐ │
│ │ 用户记忆(5条)  会话记忆(5条)  全局记忆(5条)  策略概览       │ │  ← 4 列卡片
│ │ [查看全部→]   [查看全部→]   [查看全部→]   [查看全部→]      │ │
│ ├─────────────────────────────────────────────────────────┤ │
│ │ 溯源分析：最近会话消息（5条，含 trace_id，点击跳溯源 Tab）  │ │  ← 横向表格
│ └─────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│ 原有分析区：KPI 卡 / 行为时序 / L0 事件构成 / 会话排行（保留） │
└─────────────────────────────────────────────────────────────┘
```

## 数据源映射（全部复用现有 API，无后端改动）

| 板块 | 数据源 | 展示内容 | 跳转 |
|---|---|---|---|
| 用户记忆 | `getUserMemory('admin', {limit:5})` | 条数（按类别统计 persona/preference/history/custom）+ 最近 5 条内容/类别/脱敏标记 | `tab=user` |
| 会话记忆 | `getSessionVars(sessionId, {limit:5})`，sessionId 默认取会话活跃排行第 1 的 `session_id`（无则空态） | 条数 + 最近 5 个变量 key/value | `tab=session` |
| 全局记忆 | `getGlobalMemory({limit:5})` | 条数 + 最近 5 条 key/content/脱敏标记 | `tab=global` |
| 溯源分析 | `getMessages({page:0,size:5})` + `getDistillationStats()` | 最近 5 条会话消息（角色/内容/trace_id）+ L0 事件构成摘要 | `tab=trace&traceId=xxx` |
| 记忆策略 | `getMemoryPolicy()` | 敏感过滤开关、白名单开关、脱敏规则数、白名单类别数 | `tab=policy` |

## 交互设计

1. 「查看全部」按钮 → `router.push({ path: '/agent-memory', query: { tab: '<对应tab>' } })`，复用 MemoryManageTabs 现有 URL 直达机制。
2. 溯源区每条消息若有 `trace_id`，点击「查看链路」→ 携带 `traceId` 跳转溯源 Tab，自动加载事件链。
3. 会话记忆无活跃会话时显示空态提示「暂无活跃会话，可在会话记忆 Tab 输入会话 ID 查询」。
4. 刷新按钮统一触发五类数据 + 原有分析数据的并行加载（`Promise.all`），单类失败不影响其他板块。

## 改动文件

| 文件 | 改动 |
|---|---|
| `frontend/modules/agentmemory/src/views/MemoryDashboard.vue` | 新增「记忆数据速览」区块（5 板块卡片 + 溯源消息表），扩展 `loadAll` 并行加载五类数据，新增跳转方法 |
| `frontend/modules/agentmemory/src/api/memory.js` | 无需改动（接口均已存在） |
| 后端 | 无改动 |

## 验证方式

1. `cd frontend/web-shell && npm run dev`（或已起 dev 服务）访问「记忆管理 → 记忆总览」。
2. 检查 5 张指标卡与 4 列速览卡数据正确渲染，空数据时显示空态。
3. 点击各「查看全部」正确跳转对应 Tab；溯源消息带 traceId 时点击可查看事件链。
4. 刷新按钮一次性刷新全部板块，单接口失败不影响其他板块。
5. 原有 KPI/时序/事件构成/会话排行/画像配置功能回归无影响。
